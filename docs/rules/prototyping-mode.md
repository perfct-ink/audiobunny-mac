## Prototyping Mode

Applies only when the repo's `docs/project/settings.md` sets `Prototyping mode: on`, or the user says it's on for the session (see [project-settings.md](project-settings.md)). It is off by default. When on, it overrides the branch, pull request, and push rules in [conventions.md](conventions.md) and [backlog-mode.md](backlog-mode.md); everything else still holds.

- **Ordinary changes.** Work directly on main without pull requests. For backlog tasks, use the branch workflow below so unfinished work stays on its own branch.
- **Commit and push completed ordinary changes to main.** Commit each coherent change with a `git log`-style message and push it to main without asking. `git fetch` and rebase onto `origin/main` first so you never overwrite newer work.
- **Keep the checks.** Still run the tests and lint you can, and say plainly which you couldn't run. Never push a change you know breaks the build or the tests.
- **Deploys.** If pushing main triggers a production deploy (see the project's deployment doc), prototyping mode authorizes that push; the "hands off production" limits in [deployment.md](deployment.md) still apply to everything else.
- **Backlog tasks.** Follow [backlog-mode.md](backlog-mode.md)'s uninterrupted loop, branch-per-task workflow, and completion markers. Start each task on its own `backlog/*` branch from up-to-date `origin/main`. Push every branch from the moment it's created and after each commit, whether finished or not (see backlog-mode.md), including incomplete, blocked, or unverified work, and continue to the next task without asking; never merge it to main.
- **Merge completed backlog features automatically.** Once a backlog branch meets every `Backlog-Status: complete` requirement, fetch and rebase it onto the latest `origin/main`, resolve conflicts, and rerun the required checks on the result. If integration leaves work or verification outstanding, mark the branch incomplete and continue with other tasks. Otherwise rebase merge the completed branch into main (fast-forward; see Branches in [conventions.md](conventions.md)) and push main without asking or opening a PR. This merge and push are pre-authorized in prototyping mode. Then start the next task from the updated main. If a merge or push is blocked by repository permissions or protections, preserve the branch and record the blocker; continue independent backlog work.
- **Delete merged backlog branches.** Once the merge is on `origin/main` (the push of main succeeded), delete that branch both on `origin` (`git push origin --delete backlog/<task>`) and locally (`git branch -d backlog/<task>`). This is pre-authorized in prototyping mode and applies only to the `backlog/*` branch you just merged, never to an incomplete, blocked, or unmerged branch, and never if the merge or the push of main failed. If the delete is refused (repository protections, or `-d` says the branch isn't fully merged), leave the branch, name it in your report, and continue without asking.
- **Turning it off.** When the user says prototyping mode is off, or the settings file says `off`, return to the normal branch and PR workflow.
